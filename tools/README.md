# The tools

Written for: a person or an agent who runs or changes a tool of this repo.

Run a tool from the repo root with `python tools/<name>.py` (Python 3.12 with Pillow; the
batch files at the repo root take the interpreter from `local.bat`). Each tool answers
`--help` or has its command in its docstring. A tool in `tools/` finds the shared modules
(`common.py`, `session.py`) by its own folder; a tool in a subfolder adds `tools/` to its path
itself. The places of this machine that a tool needs come from `local.json` at the repo root
(`common.local`; `local.example.json` names the keys), with a default next to this repo or
under the home folder. A worktree without `local.json` reads the main checkout's file, and the
tool names that file and its keys on stderr. Every key of that file then applies to the
worktree: give a worktree its own `local.json` for a key that must differ in it. The docs
repository (moreFPS: the harness, the state-page scripts, the batches) is always the one next to
the main checkout, never one next to a worktree (`common.docs_root`): a group of worktrees in
C:/tmp can hold a docs worktree of an old branch. The key `docs` names another docs tree, a
branch under test, on purpose; the tool then names that tree and its branch on stderr. The keys
`harness` and `obs_record` name one folder each and come before `docs`.

## The gates

| Tool | What it is |
| --- | --- |
| `validate_retained.py` | The checks of the retained pipeline, one stage at a time: `capture`, `baseline`, `only`, `clusters`, `weathers`, `tour`. The gate of a change. The baseline stage records the adapter of the accepted pictures (`accepted/adapter.txt`) and names it with the result. The capture and baseline stages also require 0 scenes with draws of their world in the target before the extension's parts began (the helper's report line `early world draws:`); the baseline stage first runs `stream_rule.py` on every kept capture (its own, the tour's and `instance/`'s) and fails when a scene of the player's views differs in projection from the world scene, or when no kept capture holds a scene of kind 5 (NOT RUN); `--self-test` tests its pure parts (`checks.py` does). |
| `stream_rule.py` | The stream rule of the gate: in each frame of a capture, the scenes of the kinds 2 to 6 (sorted alpha, water, the shadow camera's two, first person) must have the projection terms `_11` and `_22` of the world scene of the frame, within 1e-4; kind 7 is left out by name. Exit code 0 pass, 1 fail, 5 NOT RUN (no scene of kind 5: no actor in shadow range). The reference is the world scene, not the helper: the replay compares mode gpu with mode off, and both read the stream. Risk 76 was this fault. `--self-test` plants the fault itself. |
| `validate_tour.py` | The stops of a tour of a test level replayed and compared with a baseline. |
| `fuzz_capture.py` | A capture file corrupted at seeded random places (bytes flipped, a record's head changed, the file cut inside or between records; each mutation printed) and each mutant replayed with a `nirender-host.exe`: it passes when no replay aborts and every cut inside a record is refused or skipped with a line; a changed head may pass as valid data (a tag changed into another known tag is a valid record). `--self-test` tests its pure parts (`checks.py` does). |
| `checks.py` | The content checks that need no compile, as one list for each repository (`plugin`, `mge`, `all`): the readme, the contract, MWSE's native ABI, the module headers and the skills' names, and the self-tests of the tools. | `install_hooks.py` | Writes the pre-commit hooks that run `checks.py` against the tree the commit is in (`git rev-parse --show-toplevel`): this repository with that tree's own tools, the MGE XE repository in every worktree that has the renderer (`checks.py mge --mge <tree>`; a tree without `mgeHost64/src/renderer.rs` is skipped with a line), and the docs repository (through its own `--install-hook`). `git commit --no-verify` skips a hook once. `--self-test` checks the hook texts (`checks.py` does). |
| `check_readme.py` | README.md against the code: every switch the code reads, every path README names, a row here for every tool. |
| `check_format.py` | `cargo fmt -- --check` in each Rust root of this repository (the folders of its tracked Cargo.toml files), or with `--mge DIR` in the MGE XE workspace (without `--all`, which would also check the host crate here); `checks.py` runs it in both hooks; `--self-test` checks a formatted and an unformatted crate. Its output goes to a buffer, never to a pipe that closes early (rustfmt panics on a closed pipe). |
| `check_counted_objects.py` | The GPU objects are made through the counted calls of `host/src/objects.rs` (`counted_bind_group` and so on; D288): it fails on a `create_*` call of the device or of a texture anywhere else in the host crate, or with `--mge DIR` in the helper (`mgeHost64/src`), as a method call or by the path of the method. Comment lines are not code. `checks.py` runs it in both hooks; `--self-test` tests the search. The limit: it reads text, so a call through a function of another name that wraps a `create_*` call in another crate is not found. |
| `build_id_tree.py` | The build id names the work tree that was built, also when two work trees share a target folder (W339): two work trees of a scratch repository, with the build_id.rs and the `[env]` table of this repository or of `--repo DIR` (MGE XE), build on one target folder in the order A, B, A, B, B. | `check_mwse_sites.py` | The patch sites of a built MWSE.dll against the ports, before it goes to a test install (Brief 22): its 32-bit operands (`push`, `mov r32`, `mov [m]`, aligned data) inside the functions of the table, by the rules of `src/mwse_sites.rs` (census only, ENTRY, HEAD, BODY), with `mwse_sites.baseline` (value, form, count, why). | `check_clip_products.py` | No new absolute clip product in the helper's WGSL (W49): a matrix times a world position, `matrix * vec4f(world, 1.0)`, rounds apart far from the origin. It reads `mgeHost64/src` of the render-link tree (`--mge DIR`), finds each such product, and fails on one that is not on its allow-list (the known model-to-world and depth products, and `clip_with` itself). The fix is `clip_with(matrix, world)` with a matrix relative to the eye. Two stage rules close the gap of the text search: every `out.position = ...;` of a vertex stage is `clip_of(...)`, `clip_with(...)` or a local `clip` made with one (the other forms, such as a screen triangle, are on its allow-list), and no stage reads `u.view_projection`. The limit: it reads text, so a position made by a helper function of another name is not found, and the stage rules do not find a local `clip` assigned again before `out.position = clip;`, a vertex stage in the return form (`-> @builtin(position) vec4f { return ...; }`, the screen triangles today) or a mixed value such as `clip * 0.0 + s.m * p`. `--self-test` tests the search, with the planted faults. |

## The pictures and the captures

| Tool | What it is |

## `ports/`: writing a port

The tools of `PORTING.md`. Three of them run inside IDA Pro (`ida_*.py`).

| Tool | What it is |
| --- | --- |
| `ports/ida_export_inventory.py` | In IDA: the inventory of the renderer functions and the struct layouts, to `tools/out/*.json`. |
| `ports/ida_dump_funcs.py` | In IDA: the pseudocode and the disassembly of each function, to `tools/out/dump/<address>.txt`. |
| `ports/ida_abi_audit.py` | In IDA: the registers a caller reads after each call, to `tools/out/abi.json`. |
| `ports/gen.py` | `src/gen/layouts.rs` and `src/gen/funcs.rs` from the IDA export; `--layouts-only` leaves the function table and its bytes alone. A struct gets into the layouts through `LAYOUT_RE`. |
| `ports/layout_lookup.py` | The members of an IDA struct at given offsets, with the names `gen.py` gives them: the name for a hand-written offset that moves into the layouts. |
| `ports/add_touch.py` | The execution counter at the top of each port function. |
| `ports/merge_port.py` | A port branch merged into the current branch, its module registered. |

## `rig/`: the comparison rig

The runs that compare the Rust code with the game code on a real Direct3D 8 device (the
mode shadow and the frame comparison). They build the plugin with the cargo feature `rig`.
Not used since 2026-10-11; they stay for a comparison run of a port.

| Tool | What it is |
| --- | --- |
| `rig/run_test.py` | The plugin built, installed into the testing instance, and the in-game test of the ports in shadow mode with the frame comparisons. |
| `rig/compare_runs.py` | The dumps of two game runs compared (`run_test.py --dump` makes them). |
| `rig/run_perf.py` | Frame times with the game code against frame times with the Rust code. |
| `rig/run_video.py` | Two OBS clips of the same view: the game code and the Rust code. |

| `rig/run_stream.py` | The game and the host program together, the stream in shared memory, the host in its own window. |
